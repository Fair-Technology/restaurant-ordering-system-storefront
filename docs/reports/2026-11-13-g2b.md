- `src/hooks/useDocumentTitle.ts` (new): route-aware hook; `src/App.tsx` mounts it via a tiny `DocumentTitleSync` component inside `<Router>`.

## Requirements as implemented
1. **Single `<title>`.** Sets `document.title` only; no JSX `<title>`/`<meta>` → the shell's one `<title>` is mutated in place (asserted: `head > title` count = 1 on every route).
2. **Navigation-only on first load.** The first render is skipped; a deep link keeps the Function-set title and the hook acts only on client-side route changes (asserted by a deep-link test that resolves the shop name and still expects the server title).
3. **Baseline restore.** Baseline is the shipped shell title `Restaurant Ordering System` (matches `index.html`). Restored on `/` and `/legal/sub-processors`. While a newly navigated shop is loading, the previous shop's name is replaced with the baseline rather than left stale.
4. **No path-derived text.** Title is the shop name only; nothing from the path or query reaches `document.title`. Asserted on `/shops/a/orders/<id>?t=<token>` — the title is the shop name and contains no id/token fragment.
5. **`<title>` only.** No `og:*` written from the client (asserted: 0 og meta); no static `noindex` added; no `api/` or route-rule changes.

## T8 (from the G2 matrix)
`/shops/a` → `/shops/b` → `/` by pushState (no reload, asserted with a window flag): title tracks `Shop Alpha`, `Shop Beta`, then the baseline. Two rows of assertion: it tracks each shop **and** reverts on `/`.

## Decisions / caveats
- `SHELL_TITLE` is a constant duplicated from `index.html`. Requirement 3 says "read the shipped shell title once"; on a non-shop deep link the hook does read `document.title`, but on a *shop* deep link the live title is already per-shop, so the constant is the only faithful baseline. If the shell title changes, update the constant (a comment in the hook says so).
- Tests mock the API with `page.route`; no live/deployed environment was used. The live T8 belongs in the `rs-e2e` contract job against the deployed SWA.
- Vite "outside serving allow list" font warnings in the worktree are environmental (worktree + hoisted `node_modules`) and unrelated to this change.
- No `api/` changes; the parent card `t_1c4facc8` owns that side.
