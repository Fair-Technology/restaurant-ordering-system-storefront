## Decision taken (hosting) — option (a), SWA-managed Function in `rs-storefront/api`
Recommended option; chosen so work could proceed unattended. Reversible: switching to (b) only changes
how `BACKEND_API_BASE_URL` is reached (the Function code, route rule and contract are identical).

## What shipped
- `api/src/lib/shell.js` — pure logic (unit-tested). `api/src/functions/shopShell.js` — HTTP trigger `/api/shopShell`, anonymous.
- `staticwebapp.config.json` — added `routes`: `/shops/*` and `/legal/*` → rewrite `/api/shopShell` (NOT navigationFallback, so `x-ms-original-url` keeps the original URL).
- Workflows: `api_location: 'api'` (preview), `--api-location ./api` on both `swa deploy` calls (dev + promote), and `npm ci/test --prefix api` in the test job.
- Contract implemented: shell fetched live from `<x-ms-original-url origin>/index.html` (per-origin cache 60s, last-good on failure); meta per-shop cache 5 min (30s negative cache); shop read 1s timeout; shell fetch 2s; `noindex` (meta + `X-Robots-Tag`) unconditional, path-derived, before any fetch result is consulted; og:* only on exactly `/shops/<slug>`; HTML-escaped; og:image hero→logo→`/vite.svg`, absolute https only; og:url canonical; every path returns 200 (never 3xx/5xx), `redirect: 'error'` on fetches; both-hops-fail → inline minimal page (noindex, no og, no asset refs). `/` is not routed, so stays indexable.
