## Decisions recorded (round-1 review)

**1. `og:image` static fallback is now a raster, not `/vite.svg`.**
Social crawlers (WhatsApp/Facebook/Bing) do not render SVG, so the old fallback made every shop with no
hero and no logo — exactly the T3 fixture — unfurl with no picture, the grey-box failure this packet
exists to remove. Landed `public/og-fallback.png`, a 1200×630 PNG (dark card, "Order online"), and
repointed `FALLBACK_IMAGE_PATH` to `/og-fallback.png`. It is served anonymously from the storefront
origin at 200 with no SAS, which is what T3 asserts. `public/vite.svg` is left in place (Vite default).

**2. Backend response shape — confirmed against `rs-backend` (no longer an assumption).**
`getShopBySlug/index.ts` is `authLevel: 'anonymous'`, route `shops/slug/{slug}`; `mapResultToHttp`
returns `jsonBody: result.data`, i.e. the DTO **directly**. No DTO-level response envelope, so
`raw.shop ?? raw.data ?? raw` resolves to `raw`; `branding` is `ShopBranding | null`, so
`shop.branding ?? {}` covers it; `createShop`/`updateShop` validate `heroImageUrl`/`logoUrl` must start
with `https://`, matching `absoluteHttps`. City lives at `address.city`.

**3. `x-ms-original-url` is now host-pinned (SSRF guard).**
`parseOriginalUrl` takes the Host / `X-Forwarded-Host` the request actually arrived on and rejects the
header when its hostname differs (port-insensitive). Without it, a direct `GET /api/shopShell` with a
hand-set `x-ms-original-url: https://other.example/…` made the Function fetch another host's
`/index.html` and re-serve it under this origin (same-origin HTML injection). On mismatch the response
is the 200 + `noindex` minimal page — no fetch, no third-party HTML. If neither host header is present
the guard is a no-op (unchanged behaviour). **Deployed verification needed:** confirm SWA sends the site
host in `Host` on a `/shops/*` rewrite; if it sends an internal host instead, legit `/shops/*` would
fall back to the minimal page (still 200 + `noindex`, never a de-index risk, but no SPA bootstrap).
